# 架构说明

> 本文记录的是历史 27B 档位；Kiln 支持替换本地模型。当前 9B 默认模型与切换方式见 [`MODEL.md`](../MODEL.md)。

本地 Qwen3.8-27B（4bit MLX）的聊天系统合同。实现按这份来。

## 为什么前端用 Vite + React？

这是本机单用户工作台，不需要 SEO、不需要服务端渲染。FastAPI 已经负责存聊天、数 token、转发给 mlx。再用 Next.js 会多一个 Node 服务，没好处。

本机 `:3000` 和 `:8000` 已被别的项目占用，所以网页用 **5173**，API 用 **8787**。

界面：左历史、中对话、右 Context。消息是文档流，不是气泡。默认白底，粉色只做按钮/选中/进度条。

## 为什么后端用 FastAPI + SQLite？

1. tokenizer 就在模型目录里，token 统计适合用 Python。
2. `mlx_lm.server` 已经是 OpenAI 兼容 HTTP。Kiln 后端**禁止** `import mlx`、禁止再加载 14GB 权重。
3. 单用户用 SQLite（WAL）足够。
4. 以后 Agent / 多模型：走 `ChatProvider` 接口，mlx 只是第一个实现。

## 怎么接到模型

```
浏览器 :5173  →  FastAPI :8787  →  mlx_lm.server :8081  →  qwen3.8-27b/
```

模型进程必须在 macOS 上跑（Metal），不要放进 Docker。

每次请求：

- `POST http://127.0.0.1:8081/v1/chat/completions`
- 每次都发**完整** `messages[]`（server 不记会话；靠 token 前缀命中缓存）
- `model` 固定 `"default_model"`，避免 mlx 把字符串当另一条模型路径去加载
- `stream: true` 且 `stream_options.include_usage: true`
- 采样：温度 1.0，top_p 0.95，top_k 20
- 默认最多生成 2048 token，硬顶 8192（理论窗口 262144 不能当真）

流里思考字段叫 `delta.reasoning`，下一轮模板读的是 `reasoning_content`，后端负责改名。

## 聊天怎么存

`kiln/data/chat.db` 是唯一真相。前端只是界面。

`POST /chat` 只提交**这一句用户话** + 可选 `conversation_id`。后端自己拼历史、截断、压缩、再调模型。

## Context 怎么看

发给模型之前先写一条 snapshot，SSE 第一个事件就是它。右侧面板显示：

- 真正的 system prompt
- 实际送出的 messages
- 是否截断 / 压缩摘要
- 输入 / 输出 / 总量 / 缓存 token
- 占用条：分母是实用窗口 8192，不是 262144

## 记忆以后怎么扩

表已经建好：`memories`、`memory_evidence`、`embeddings`。

检索结果只能用 `<memory>…</memory>` 贴在**最新用户那一句旁边**，永远不要写进 `role=system`（否则会打爆前缀缓存，也容易把「记忆」变成永久越狱）。模型提议的记忆默认不自动入库。
