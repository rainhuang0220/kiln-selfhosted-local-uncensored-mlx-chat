# 推理框架对比（M4 24GB，Qwen 27B 4bit）

这台电脑**现在**的情况：

| 工具 | 是否安装 | 说明 |
|---|---|---|
| MLX-LM 0.31.3 | 是（Python 3.12 虚拟环境） | 本仓库 27B：`npm run start:mlx` → `:8081` |
| MTPLX 2.9.1 | 是（`models/.mtplx-venv`） | 官方 MTP 权重；4B/9B 已拉到 `~/.mtplx/models`。`npm run start:mtplx` → `:8082` |
| llama.cpp / llama-server | 否 | 需要先转 GGUF |
| Ollama | 否 | |
| LM Studio | 否 | |

## 对照表（没测就不填）

| 框架 | 解码速度 | 首字时间 | 显存/内存 | 上下文 | 流式 |
| --- | ---: | ---: | --- | --- | --- |
| MLX-LM 27B | **6.63 tok/s 解码**，1k prefill 62 | 冷 2.7s / 缓存 0.74s | 权重 14.1GB | 实用 8k | OpenAI SSE |
| MTPLX 9B | **24.2 tok/s**，prefill 171 | ~0.77s | 权重 8.1GB | 官方 MTP | OpenAI SSE `:8082` |
| MTPLX 4B | **52.1 tok/s**，prefill 327 | ~0.41s | 权重 2.4GB | 官方 MTP | OpenAI SSE `:8082` |
| llama.cpp | 未测 | — | — | — | — |
| Ollama | 未装 | — | — | — | — |
| LM Studio | 未装 | — | — | — | — |

**结论：** 继续用这份 uncensored 27B 就留在 MLX-LM，解码就是 ~6.6 tok/s。要 ≥30 tok/s 只能换更小的、带 MTP 的 MTPLX 权重（本机验证过的是 4B）。不要为了这份 AEON 27B 去装 llama.cpp——它同样读 14GB 权重，带宽上限差不多。

以后若要再比：转 GGUF → 装 `llama-server` → 用同一套 `benchmarks/run_inference.py` 打 OpenAI 兼容端口，把数字追加进表。
